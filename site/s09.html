进阶 · 关键片段

跨会话记住该记的Memory

把以后还会用到的信息留下来

解决什么问题 · 每开一个新会话都从零开始：昨天定下的约定、这个项目的坑，今天还得再说一遍。把整段历史都带上又太重。

思路

  1. 记忆写成 markdown 文件，外加一份索引（名字 + 一句话）；
  2. 每轮结束抽取候选记忆，先判断值不值得记、是否重复，再写盘并重建索引；
  3. 下一轮开始时，把「目录 + 当前请求」给模型，让它挑编号召回；
  4. 模型不可用就退回关键词匹配——记忆坏了不能拖垮主流程。

记住这几条

两级结构

索引常驻（便宜），正文按需（贵）。和 s07 技能加载是同一个套路。

召回要有 query

拿当前用户请求去匹配，而不是把所有记忆一股脑塞进去。

写入发生在轮末

这一版在每轮结束后抽取候选记忆并整理索引，不是边聊边写。

一定要能降级

模型挑选失败 → 关键词匹配；匹配失败 → 不召回。

容易踩的坑

  • 什么都记：一次性的调试细节也写进去，下次召回全是噪声。
  • 记忆和当前代码冲突：记着「用 npm」，但项目早换 pnpm 了，模型会照记忆办事。
  • 召回条数不设上限，一次塞进十条长记忆，上下文直接见底。

动手改一改

让它记住「这个项目用 pnpm，不要用 npm」，然后开一个新会话直接问「装个依赖用哪个命令」。验收：新会话里模型引用了这条记忆，或回答里明确说「按记忆用 pnpm」。
