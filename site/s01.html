一个循环就够了Agent Loop

一个工具 + 一个循环 = 一个 Agent

解决什么问题 · 模型只会说话不会动手。要让它干活，你得给它一条「行动—观察—再行动」的回路。这一章用 40 行左右把回路写出来，后面每一章都是往它外面加东西。

思路

  1. 把「有一个 bash 工具」这件事，用 JSON Schema 告诉模型；
  2. 发请求，拿回复；回复里除了文字，还可能有 tool_use（模型说：帮我执行这个）；
  3. 你执行完，把结果包成 tool_result 塞回 messages；
  4. 再发一次请求，模型看到结果继续决策——直到它不再要工具。

记住这几条

四步循环

问模型 → 执行工具 → 回填结果 → 再问。本课程后面每一章都沿用这个骨架。

停止 = 模型不再要工具

代码不判断任务完成度，这是 s17 Goal Loop 要补的洞。

模型无状态

messages 就是它的全部记忆，每轮完整传回，所以上下文管理（s08）才重要。

错误也是结果

工具失败返回字符串而不是抛异常，模型才能读到并自己纠错。

容易踩的坑

  • 回填 tool_result 时漏了 tool_use_id，或 id 对不上，API 会直接 400。
  • 忘了设 timeout 和输出截断，一条 `yes` 就能让会话一直转下去。
  • 把 tool_result 塞进 assistant 消息里，协议不认——它必须放在 user 消息中。

动手改一改

把 SYSTEM 里的 "Act, don't explain." 删掉，再问「看看这个目录有什么」。验收：回答明显变长、开始解释而不是直接调用 bash。改完记得改回来。
