先列清单再动手TodoWrite

清单由工具维护，连续 3 轮不更新才提醒

解决什么问题 · 长任务里模型做着做着就忘了还剩什么：第三步漏了、同一件事做两遍。但这一章的解法不是「每轮把清单塞进提示词」，而是让模型自己用工具维护，只在它连续 3 轮没更新时，追加一条提醒。

思路

  1. 清单存在进程内存里的 TodoManager，模型通过 todo_write 一次性提交整张表；
  2. 每次提交都校验（最多 20 条、状态合法、只能一条 in_progress），渲染结果作为工具结果返回；
  3. 循环里数「连续几轮没碰 todo_write」，到 3 就在工具结果后追加 <reminder>；
  4. 清单不会自动进 system prompt——模型看到的是工具结果和这条提醒。

记住这几条

清单在进程里，不在提示词里

本版没有把 todo 列表注入 system prompt 或每轮上下文。

工具结果回显整张表

模型每次调用 todo_write，都会拿到渲染后的清单。

连续 3 轮才提醒

`rounds_since_todo >= 3` 时追加一条 <reminder>，然后清零。

上限 20 条、一条 in_progress

校验失败会返回错误字符串，模型能读到并修正。

提醒是软的

模型可以无视这条提醒，继续干别的——它只是提示，不是强制。

容易踩的坑

  • 别把这一章理解成「每轮自动注入清单」——源码里没有这段逻辑。
  • 清单只在内存里，进程退出就丢；要跨会话保留，得看 s10 的任务系统。
  • 提醒追加在工具结果里，模型偶尔会忽略；它不是强约束。
  • 一次提交超过 20 条，会直接返回 `Error: Max 20 todos allowed`。

动手改一改

把 `if rounds_since_todo >= 3:` 改成 `>= 1`，再做一件需要五六步的事。验收：每次工具结果后都能看到 `<reminder>Update your todos.</reminder>`，模型调用 todo_write 的次数明显变多；改回 3 再对比一次。
