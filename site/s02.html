加工具只加一行Tool Use

循环不用动，新工具注册进 dispatch map 就行

解决什么问题 · 只有 bash 时，模型读文件要 cat、改文件要 sed，既容易写错，也没法限制它乱翻文件。这一章加四个专用工具（读、写、改、找），把「调哪个函数」从硬编码变成查表。

思路

  1. 每个工具 = 一个 handler 函数 + 一份 JSON Schema；
  2. 所有 handler 收进一张字典 TOOL_HANDLERS，工具名 → 函数；
  3. 循环里把 run_bash(...) 换成 TOOL_HANDLERS[name](**args)；
  4. 所有文件路径先过 safe_path，出不了工作目录。

记住这几条

加工具 = schema + handler + 表里一行

在这套 dispatch 结构里，加工具不需要碰循环。

先 resolve 再判断

路径安全检查必须在解析完 .. 和符号链接之后做，否则形同虚设。

参数名必须对齐

schema 里的 key 就是 Python 的 kwarg 名，错一个字母就是 TypeError。

工具只返回字符串

成功、失败、空结果，一律是字符串；模型的世界里没有异常。

容易踩的坑

  • 用 `WORKDIR / p` 但不 resolve，`../` 一路能跑到根目录。
  • edit 用 replace 不带次数限制，改一处结果全文件同名代码都被改了。
  • read 不限行数，模型一条命令读了 5000 行日志，这一轮的上下文基本就废了。
  • 注意：safe_path 只约束「文件工具」的路径，bash 仍然能访问工作区外的任何东西——它不是沙箱。

动手改一改

加一个 `list_dir` 工具：写 handler、加一段 schema、在 TOOL_HANDLERS 里加一行。验收：循环代码一个字没改，模型能成功调用它；再给 read_file 传 `../../etc/hosts`，应返回 `Error: Path escapes workspace`。
