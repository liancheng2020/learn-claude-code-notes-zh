任务落盘，进度可恢复Task System

依赖「未完成」才阻塞，列表非空不算

解决什么问题 · s05 的清单只在内存里，进程一挂就没了；而且没有依赖关系，A 还没做完就去做 B。这一章把任务写成文件，加上状态和依赖——但注意它没有并发保护。

思路

  1. 每个任务一个 JSON 文件，状态只有 pending → in_progress → completed；
  2. blockedBy 存依赖 id，认领前检查的是「这些依赖里还有没有没完成的」；
  3. id 用随机 hex，靠「独占创建」保证不撞名；
  4. 完成任务时校验状态和 owner；这一版没有文件锁。

记住这几条

文件即存储

一个任务一个 JSON，可视化、可手改、可 diff。

依赖看「完成没」

blockedBy 里有值不代表被挡；只有其中存在未完成（或找不到）的任务才阻塞。

状态单向

pending → in_progress → completed，没有回退和取消。

没有并发保护

两个进程同时 claim 同一个任务，可能都成功——锁是 s13 才加的。

完成才校验 owner

complete_task 会检查 status 和 owner；claim 时不检查 owner。

容易踩的坑

  • 把「blockedBy 非空」当成「不能开工」——实际只挡未完成的依赖。
  • 在多进程/多 agent 场景直接用它：没有锁，会重复认领。
  • 依赖的任务文件被删了：加载失败也算「未完成」，于是一直被挡住，直到文件恢复。
  • 手改 JSON 改坏了结构，load 时会直接抛错。

动手改一改

按顺序做：① create_task 建 A、B、C、D 四个任务，记下 id；② update_task(B, addBlockedBy=[A])、update_task(D, addBlockedBy=[C])；③ claim_task(B) → 返回 `Blocked by: [A]`；④ claim_task(A) → `Claimed`，再 complete_task(A) → `Completed`；⑤ claim_task(B) → 这次返回 `Claimed`；⑥ 删掉 `.tasks/<C>.json` 后 claim_task(D) → 返回 `Blocked by: [C]`（缺失的依赖也算未完成）。注意 complete_task(A) 前必须先 claim_task(A)，否则会因为状态不是 in_progress 被拒。
