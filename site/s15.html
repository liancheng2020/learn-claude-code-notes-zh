把前面的机制装进一个循环Integrated Harness

一个循环 + 两个注册表

解决什么问题 · 前面每章都是独立 demo。真实系统要把工具、权限、钩子、记忆、任务、团队、插件装在一起，而且不能互相打架——这一个文件有 3000 多行。

思路

  1. 仍然是一个 while 循环：每轮装配工具池、准备上下文、调模型、分发工具；
  2. 工具池 = 内置工具 + 所有 MCP 工具，每轮重新合成；
  3. 权限、日志、大输出、收工统计全是 hook，不是循环里的 if；
  4. 定时任务、后台通知、todo 提醒、上下文压缩都在循环头尾按顺序发生。

记住这几条

一个循环 + 两个注册表

工具池（能做什么）和 hook 表（什么时候插一脚），其余都是装配。

工具池每轮重建

MCP 中途连上也能立刻用；代价是每轮有点开销。

权限是 hook，不是 if

想换策略就换注册的那一行。

循环头尾有顺序

定时 → 后台通知 → todo 提醒 → 压缩 → 调模型；顺序影响行为。

生产化的事源码没做

「配置开关」「初始化幂等」「错误定位」在本文件里没有实现，属于你自己要补的工程工作。

容易踩的坑

  • 从头读 3000 行，读到一半就迷路——先看这三个注册点：assemble_tool_pool、HOOKS、agent_loop。
  • 以为它已经能多租户/多会话隔离：它仍是一个进程、一份全局状态。
  • 拿它直接上生产：没有配置校验、没有优雅停机、没有指标，这些都得自己加。

动手改一改

在 s15 里只搜三处：`assemble_tool_pool`、`trigger_hooks`、`prepare_context`。验收：能说出「一轮循环里工具池被装配几次、PreToolUse/PostToolUse 各在哪触发、压缩在哪一步执行」，并在文中找到对应行号。
