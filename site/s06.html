子任务给一段干净上下文Subagent

子 agent 从全新的 messages[] 开始，只把结论带回来

解决什么问题 · 让主 agent 去「研究一下这个仓库」，它要读几十个文件。这些内容全留在主上下文里，几轮就满了，而且大部分细节以后根本用不上。

思路

  1. task 工具启动一个子循环，messages 从零开始；
  2. 子 agent 有自己的一套工具和 system prompt；
  3. 跑完只把最后那段文字返回给父 agent；
  4. 中间读了什么、调了什么，全部丢掉。

BASE_HANDLERS 里没有 task，所以子 agent 拿不到 task 工具——天然防止无限套娃。

记住这几条

子 agent = 一段新对话

同一进程、同一套工具、全新的 messages。

只回传结论

中间过程留在子上下文里，随它一起销毁。

必须有上限

轮数上限 + 失败兜底，否则父循环会被拖死。

prompt 要自包含

子 agent 看不到父对话，背景、路径、验收标准都得写清楚。

隔离的只有上下文

子 agent 与父 agent 同进程、同文件系统、同权限；该删的文件照样删得掉。

容易踩的坑

  • 子 agent 抛异常或超时没有兜底，父循环直接卡住。
  • 让子 agent「顺便看看这个变量」，但它根本看不到父对话里的变量。
  • 子 agent 也给了 task 工具，于是它自己又开子 agent，递归到天荒地老。
  • 把子 agent 当成安全沙箱：它拿到的是同一套工具、同一个工作目录，只是 messages 干净。

动手改一改

把 `for _ in range(30)` 改成 `range(3)`，再做一件需要读很多文件的任务。验收：子 agent 提前停下，父 agent 收到 `Subagent stopped after 30 turns...` 这类提示，而不是卡死。
