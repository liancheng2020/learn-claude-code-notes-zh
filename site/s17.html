模型说完了不算完Goal Loop

另起一次无工具的模型调用做裁决

解决什么问题 · s01 的退出条件是「模型不再要工具」。但模型经常在事情没做完时就说「已完成」。让它自己判断，等于让学生自己批卷子。

思路

  1. 目标是一段可判定的条件，比如「测试全绿」「文件存在」；
  2. 每轮结束，交给一个独立的、不带工具的模型调用裁决；
  3. 没达成就再跑一轮，并告诉模型「还差什么」；
  4. 连续被挡超过阈值就返回 limit，避免无限循环。

记住这几条

判断器独立于执行者

另起一次调用，不带工具，只读 transcript 做判断。

但它仍是模型

判断可能出错：被漂亮的说法骗过，或者对证据理解偏差。不能等同于确定性的测试验收。

条件要可判定

用命令退出码、文件是否存在、测试是否通过，而不是形容词。

有止损但无 token 硬上限

连续 block 超过 block_cap 会返回 limit；代码里没有「花到多少钱就停」的硬约束。

裁决要留痕

每次判定都记录，才能调试「它为什么一直说没完成」。

容易踩的坑

  • 把独立判断器当成「客观真理」——它只是换了一次模型调用，仍会误判。
  • 目标本身不可判定（「体验要好」），判断器只能瞎猜。
  • 完全依赖它决定收工，却没有外部测试或人工验收兜底。

动手改一改

设一个「pytest 必须全绿」的目标，故意留一个失败测试。验收：判断器连续返回 block，模型回去改代码；等测试真的全绿后，下一次判断返回 achieved。再把目标改成「代码写得优雅」，观察它给出的理由有多主观。
