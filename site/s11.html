慢操作丢后台Background Tasks

慢命令放后台线程，主循环继续转

解决什么问题 · 跑一次测试要三分钟。主循环就干等着，用户也没法插话，体验像卡死。

思路

  1. 给 bash 加 run_in_background 参数；
  2. 起一个线程跑子进程，任务 id 和状态存在管理器里；
  3. 主循环每轮开头 collect 一次完成的任务；
  4. 把结果包成 <task_notification> 注入上下文。

记住这几条

只有 bash 能后台

文件读写本来就是毫秒级，没必要异步。

锁保护共享状态

后台线程 + 主线程，不加锁迟早出问题。

通知只给摘要

全文落盘，上下文里只留 id、状态、前 500 字。

整组杀进程

后台命令通常带管道，只杀父进程会留下孤儿。

这是线程，不是守护进程

进程一退，后台任务跟着没；电脑休眠也不会继续跑。

容易踩的坑

  • 以为关掉终端它还在跑——不会，线程随进程结束。
  • 后台进程泄漏：用户退出会话了，子进程可能还活着。
  • 输出无限增长：tail -f 这种命令会把内存吃满，必须有大小上限。
  • collect 调用太晚，通知堆了几十条，一次全塞给模型。

动手改一改

让它后台跑 `sleep 5 && echo done`，同时继续问它别的问题。验收：5 秒后收到一条 `<task_notification>`，里面能看到 task_id 和摘要，而主对话在这 5 秒里没有卡住。
