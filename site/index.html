看懂一个 AI 编程 Agent
是怎么造出来的

这个仓库用 17 章的 Python 示例，把 Claude Code 这类编程 Agent 拆开给你看：没有魔法，只有循环、工具、权限、上下文管理和一层层「补丁」。本教程按 commit 7226f55 讲，代码全部取自该版本的源文件。

17 章Python 基于 commit 7226f55逐行 + 分段讲解

先记住一句话：模型负责「想」，代码负责「让它能动手」

大模型本身只会输出文字。它能写出 rm -rf build，但它没有手，删不掉任何东西。 所谓 Agent，就是模型 + 一套让它能感知和行动的外壳。这个外壳，作者叫 Harness（载具）。

所以整本书不是「教模型变聪明」，而是「教你怎么造载具」：怎么把工具递给它、怎么拦危险操作、 怎么在上下文快满时腾地方、怎么让多个 Agent 分工。

先说清楚这份教程的覆盖范围

不是 17 章都「完整源码 + 逐行」。真实情况如下，章节标题旁边也有对应标签：

章节代码呈现讲解方式
s01–s02完整源码（整个 code.py）每一行都有注解
s03–s08核心源码节选（每章 1–3 段）节选内逐行注解；未选中的部分不在文中
s09–s17关键片段（每章 1–4 段）片段内逐行注解；其余机制分段说明，不冒充逐行

每个代码块右上角标了 L起–L止，可以在固定 commit 的 GitHub 原文里逐行对照。 片段之间如果有省略，会另起一个代码块，不会把不相邻的代码拼在一起。

全书的骨架，其实就 4 行

while True:
    response = LLM(messages, tools)     # 问模型
    if 没有 tool_use: break              # 它不想动手了，收工
    执行工具，把结果 append 回 messages   # 干活、记录
# 然后继续下一圈

后面 16 章，都是在这个循环外面加东西：加工具（s02）、加权限（s03）、 加钩子（s04）、加计划（s05）、加子 Agent（s06）……循环形状基本没变。 作者反复强调的就是这一点：好的 Harness 是围绕循环加装，而不是把逻辑塞进循环。

把代码跑起来（按仓库 requirements.txt）

git clone https://github.com/shareAI-lab/learn-claude-code
cd learn-claude-code
python3 -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt                         # anthropic、python-dotenv、PyYAML
cp .env.example .env 2>/dev/null || printf 'ANTHROPIC_API_KEY=\nMODEL_ID=\n' > .env
python s01_agent_loop/code.py

从仓库根目录运行：s07 会在工作目录下找 skills/，s08 会把 transcript 写到 ./.transcripts/，所有文件工具都以「启动时的工作目录」为根。换目录跑，行为会跟着变。

密钥只写进本机 .env，不要贴进对话、截图或这份 HTML。模型名（MODEL_ID） 按你自己账号能用的写，教程里的示例名不保证可用。

自定义地址必须兼容 Anthropic Messages 协议（/v1/messages、相同的请求/响应结构）， 不是随便填一个「中转地址」就能跑；ANTHROPIC_BASE_URL 只是换 base URL，不改变协议。

跑之前请知道：它会真的动你的机器

这些示例会执行 shell 命令、读写文件、发起真实的模型请求——会产生费用。 建议在一台干净的虚拟机、容器或专门的练习目录里跑，别在有密钥和重要数据的目录里试。

教程里的练习都不要求你关掉权限检查，也不建议用「默认允许危险操作」来图省事。 s03 的黑名单只是字符串匹配，不是沙箱，更不是安全边界。

这本书怎么读

第 1–2 章：完整代码，值得照着敲一遍，先把「循环 + 工具分发」的手感建立起来。

第 3–8 章：看节选，重点是每章「加在循环外面的那一层」——权限、钩子、计划、子 Agent、技能、压缩。

第 9–17 章：看机制和关键片段。s15 一个文件 3000 多行，本教程只挑主循环、工具池、hook 注册三处，够你看懂它是怎么拼起来的。

每章结构一致：解决什么问题 → 思路 → 代码 → 记住这几条 → 容易踩的坑 → 动手改一改。 文中会尽量区分「本版就是这样实现的」、「这里是教学简化」和「生产环境才会这么做」；看到「建议」「生产环境」这类词，基本说明源码里没有。

学完之后

17 章看下来，其实就三句话——但这三句都要加限定条件。

1. 循环是地基，能力长在它外面

工具是注册表、权限是钩子、上下文是包装、子 Agent 是再开一个循环。 这套课程里，加能力基本不用改 while 循环——但如果你要的是多租户、并发隔离、可观测性，那些工作不在循环里，也不在这 17 个文件里。

2. 模型负责决策，代码负责边界

让它决定调什么工具、写什么代码；但「能不能删这个目录」「上下文满了怎么办」「什么算完成」， 这些边界得由代码兜住。prompt 是建议，代码才是约束。

3. 上下文是唯一的稀缺资源

s06 子 Agent、s07 技能加载、s08 压缩、s09 记忆，四个章节都在干同一件事： 让模型在有限窗口里看到最该看的东西。这也是这份代码里最值得反复读的部分。

这份代码不是什么

它不是安全沙箱（s03 只是字符串黑名单），不是生产级多租户系统（s15 只有一个进程、一份全局状态）， 不是真实的 MCP 实现（s14 是内存 mock），也不是可靠的自动验收（s17 的判断器仍然是模型）。 把它当教材读，别当框架用。

接下来可以做什么

  • 把 s01 那份 40 行代码改成你熟悉的语言（TypeScript / Go），你会真正理解每个细节。
  • 给 s02 加一个你工作里最常用的工具，体会「加工具不改循环」。
  • 把 s03 的黑名单换成真正的命令解析，看看能防住多少绕过手法。
  • 把 s08 的阈值调小，观察一次真实的长任务里四步压缩各触发了几次。
