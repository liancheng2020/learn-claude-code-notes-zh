17 章Python 基于 commit 7226f55逐行 + 分段讲解

先记住一句话：模型负责「想」，代码负责「让它能动手」

大模型本身只会输出文字。它能写出 rm -rf build，但它没有手，删不掉任何东西。 所谓 Agent，就是模型 + 一套让它能感知和行动的外壳。这个外壳，作者叫 Harness（载具）。

所以整本书不是「教模型变聪明」，而是「教你怎么造载具」：怎么把工具递给它、怎么拦危险操作、 怎么在上下文快满时腾地方、怎么让多个 Agent 分工。

一个循环就够了Agent Loop

一个工具 + 一个循环 = 一个 Agent

解决什么问题 · 模型只会说话不会动手。要让它干活，你得给它一条「行动—观察—再行动」的回路。这一章用 40 行左右把回路写出来，后面每一章都是往它外面加东西。

思路

  1. 把「有一个 bash 工具」这件事，用 JSON Schema 告诉模型；
  2. 发请求，拿回复；回复里除了文字，还可能有 tool_use（模型说：帮我执行这个）；
  3. 你执行完，把结果包成 tool_result 塞回 messages；
  4. 再发一次请求，模型看到结果继续决策——直到它不再要工具。

记住这几条

四步循环

问模型 → 执行工具 → 回填结果 → 再问。本课程后面每一章都沿用这个骨架。

停止 = 模型不再要工具

代码不判断任务完成度，这是 s17 Goal Loop 要补的洞。

模型无状态

messages 就是它的全部记忆，每轮完整传回，所以上下文管理（s08）才重要。

错误也是结果

工具失败返回字符串而不是抛异常，模型才能读到并自己纠错。

容易踩的坑

  • 回填 tool_result 时漏了 tool_use_id，或 id 对不上，API 会直接 400。
  • 忘了设 timeout 和输出截断，一条 `yes` 就能让会话一直转下去。
  • 把 tool_result 塞进 assistant 消息里，协议不认——它必须放在 user 消息中。

动手改一改

把 SYSTEM 里的 "Act, don't explain." 删掉，再问「看看这个目录有什么」。验收：回答明显变长、开始解释而不是直接调用 bash。改完记得改回来。

循环不用动，新工具注册进 dispatch map 就行

解决什么问题 · 只有 bash 时，模型读文件要 cat、改文件要 sed，既容易写错，也没法限制它乱翻文件。这一章加四个专用工具（读、写、改、找），把「调哪个函数」从硬编码变成查表。

思路

  1. 每个工具 = 一个 handler 函数 + 一份 JSON Schema；
  2. 所有 handler 收进一张字典 TOOL_HANDLERS，工具名 → 函数；
  3. 循环里把 run_bash(...) 换成 TOOL_HANDLERS[name](**args)；
  4. 所有文件路径先过 safe_path，出不了工作目录。

挂在循环上，不写进循环里Hooks

hook 在工具执行前后注入扩展逻辑

解决什么问题 · 权限只是你想加的第一件事。以后还想加日志、审计、大输出告警、收工总结……如果每件事都去改循环，循环很快就会变成一坨意大利面。

思路

  1. 定义四个事件：用户提交、工具执行前、执行后、准备收工；
  2. 每个事件挂一串回调，由 register_hook 注册；
  3. 回调返回 None 表示「继续」，返回内容表示「拦截/注入」；
  4. 循环只调用 trigger_hooks，不知道具体有哪些扩展。

脚本定顺序，模型做单步；默认跑的是 mock

模型说完了不算完Goal Loop

另起一次无工具的模型调用做裁决

解决什么问题 · s01 的退出条件是「模型不再要工具」。但模型经常在事情没做完时就说「已完成」。让它自己判断，等于让学生自己批卷子。

思路

  1. 目标是一段可判定的条件，比如「测试全绿」「文件存在」；
  2. 每轮结束，交给一个独立的、不带工具的模型调用裁决；
  3. 没达成就再跑一轮，并告诉模型「还差什么」；
  4. 连续被挡超过阈值就返回 limit，避免无限循环。

学完之后

17 章看下来，其实就三句话——但这三句都要加限定条件。

1. 循环是地基，能力长在它外面

工具是注册表、权限是钩子、上下文是包装、子 Agent 是再开一个循环。 这套课程里，加能力基本不用改 while 循环——但如果你要的是多租户、并发隔离、可观测性，那些工作不在循环里，也不在这 17 个文件里。

2. 模型负责决策，代码负责边界

让它决定调什么工具、写什么代码；但「能不能删这个目录」「上下文满了怎么办」「什么算完成」， 这些边界得由代码兜住。prompt 是建议，代码才是约束。

3. 上下文是唯一的稀缺资源

s06 子 Agent、s07 技能加载、s08 压缩、s09 记忆，四个章节都在干同一件事： 让模型在有限窗口里看到最该看的东西。这也是这份代码里最值得反复读的部分。

这份代码不是什么

它不是安全沙箱（s03 只是字符串黑名单），不是生产级多租户系统（s15 只有一个进程、一份全局状态）， 不是真实的 MCP 实现（s14 是内存 mock），也不是可靠的自动验收（s17 的判断器仍然是模型）。 把它当教材读，别当框架用。

接下来可以做什么

  • 把 s01 那份 40 行代码改成你熟悉的语言（TypeScript / Go），你会真正理解每个细节。
  • 给 s02 加一个你工作里最常用的工具，体会「加工具不改循环」。
