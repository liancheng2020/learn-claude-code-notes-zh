单步交给模型，编排交给脚本Workflow Runtime

脚本定顺序，模型做单步；默认跑的是 mock

解决什么问题 · 多步流程里，如果每一步都由模型决定下一步，既慢又贵，而且同一份输入跑两次结果可能不同。

思路

  1. 编排写成脚本：谁先谁后、串行还是并行、失败怎么重试；
  2. 每一步仍然是一次模型调用，但只负责「这一步」；
  3. 带 schema 的输出会校验，失败重试一次；
  4. 每一步追加写 journal；恢复时按 key 命中就复用旧结果。

记住这几条

编排与决策分离

脚本管流程，模型管内容。

schema 校验 + 重试一次

agent() 带 schema 时会校验；不合法重试一次，仍失败就报错。

journal 支持续跑

按 (kind, label, prompt, schema) 生成 key，命中缓存直接复用。

默认是 mock runner

RUNNER_FACTORY = MockAgentRunner；要真跑模型得换成 AnthropicAgentRunner。

预算可观测

每步 token 都记下来，才知道钱花在哪。

容易踩的坑

  • 以为示例默认就在调真模型——默认走的是 MockAgentRunner，先看清楚再跑。
  • 把判断逻辑也写进脚本，最后退化成一台僵硬的工作流引擎。
  • journal 的 key 不含输入摘要，改了 prompt 还复用旧结果。
  • 某一步失败没有重试策略，整条流水线直接断掉。

动手改一改

把 RUNNER_FACTORY 换成 AnthropicAgentRunner，写一个三步 workflow：调研 → 实现 → 自检。验收：journal 里出现三条 agent 记录，每条带 token 数；用同一个 runId 加 resume 再跑一次，验收：已完成的步骤没有重复请求。
