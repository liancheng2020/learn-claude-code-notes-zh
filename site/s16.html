单步交给模型，编排交给脚本Workflow Runtime

demo 离线跑；只有交互 CLI 才装真实 runner

解决什么问题 · 多步流程里，如果每一步都由模型决定下一步，既慢又贵，而且同一份输入跑两次结果可能不同。这一章的 demo 默认用 MockAgentRunner，不联网、不花钱；真实模型只在交互模式里接上。

思路

  1. 编排写成脚本：谁先谁后、串行还是并行、失败怎么重试；
  2. 每一步仍是一次模型调用，但只负责「这一步」；
  3. 带 schema 的输出会校验，失败重试一次；
  4. 每一步追加写 journal；resume 时按 key 命中缓存就跳过。

记住这几条

三种入口

`demo` 离线演示、`resume` 离线续跑、无参数进入交互 CLI。

demo/resume 不花钱

默认 RUNNER_FACTORY = MockAgentRunner，返回确定性结果。

真实 runner 由 host 安装

install_workflow_tool(host) 里改成 AnthropicAgentRunner(host.client, host.MODEL)。

不能无参替换

AnthropicAgentRunner 的构造函数需要 client 和 model；直接替换类名会 TypeError。

journal 支持续跑

按 (kind, label, prompt, schema) 生成 key，命中缓存直接复用。

容易踩的坑

  • 以为 `demo` 在调真模型——它用的是 MockAgentRunner。
  • 把 RUNNER_FACTORY 直接赋成 AnthropicAgentRunner：缺少 client/model，直接报错。
  • 无参数进入交互 CLI 后没意识到会产生真实费用。
  • journal 的 key 不含输入摘要，改了 prompt 还可能复用旧结果。

动手改一改

离线练习：先跑 `python s16_workflow_runtime/code.py demo`，记下输出的 agents 数和 journal 条目数；再跑 `python s16_workflow_runtime/code.py resume`。验收：第二次的 agents 数小于第一次，且 journal 里能看到被复用的记录——全程不产生模型费用。想看真实调用，只能用无参数进入 CLI（会安装 AnthropicAgentRunner，产生费用），不要靠改类名。
