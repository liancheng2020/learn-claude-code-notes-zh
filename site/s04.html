核心节选 · 7 处注解

挂在循环上，不写进循环里Hooks

hook 在工具执行前后注入扩展逻辑

解决什么问题 · 权限只是你想加的第一件事。以后还想加日志、审计、大输出告警、收工总结……如果每件事都去改循环，循环很快就会变成一坨意大利面。

思路

  1. 定义四个事件：用户提交、工具执行前、执行后、准备收工；
  2. 每个事件挂一串回调，由 register_hook 注册；
  3. 回调返回 None 表示「继续」，返回内容表示「拦截/注入」；
  4. 循环只调用 trigger_hooks，不知道具体有哪些扩展。

L137–137

四个事件、四个列表。hook 的全部魔法就是「事件发生时，按顺序调用注册过的函数」。

L138–139

注册 = 往列表里塞一个函数。没有任何框架，也没有元类。

L140–144

返回值有语义：非 None 就表示「拦截」，后面的 hook 不再执行。这条约定让 hook 既能观察也能干预。

L145–162

s03 的权限代码原样搬进来了。行为完全一样，区别只是它不再写死在循环里，可以随时摘掉。

L163–217

看这五行注册，就知道系统里有哪些扩展点——比翻循环体清楚多了。

L218–236

Stop hook 可以返回一段文字，表示「别收工，再跑一轮」。这是「模型想停但事没做完」的第一种解法。

L237–237

把 hook 的话当成一条 user 消息塞回去，然后 continue。注意：不 continue 就直接 return 了。

记住这几条

hook = 事件 + 回调

循环只负责触发事件，不知道谁在监听。

返回值即语义

None 继续，非 None 拦截或注入——一条约定撑起所有扩展。

权限可以搬家

s03 的逻辑原样搬进 PreToolUse，说明「机制」和「策略」分开了。

Stop 可以拒绝收工

这是后面 s17 独立判断器的雏形。

容易踩的坑

  • 在 hook 里做联网、跑模型这类重活，每一步都会被拖慢一次。
  • 一个 hook 抛异常，整条循环就挂了——hook 内部要自己 try。
  • Stop hook 返回了内容却忘了 continue，等于白说。

动手改一改

加一个 PreToolUse hook，把每次 bash 命令写进临时日志文件；再加一个 PostToolUse hook 统计工具调用次数。验收：日志文件里出现每条命令，且 agent_loop 一个字没改（用 git diff 确认）。
