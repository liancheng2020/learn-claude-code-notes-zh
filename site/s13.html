多个 Agent 抢任务Agent Teams

文件锁 + 一个进行中任务 + 可选 worktree

解决什么问题 · 任务多了要并行。一旦并行，就会抢同一个任务、互相踩同一个文件。

思路

  1. 共享任务板（s10 的文件任务）+ 一把锁；
  2. 认领必须在锁里完成「读—检查—改—写」；
  3. 一个队友同一时间只能干一件事；
  4. 可选 worktree：显式创建并绑定后，队友才有独立工作目录。

记住这几条

认领要原子

不加锁的「先查再改」，并发下可能抢到同一个任务。

一个 owner 一件事

限制并发度，比事后收拾半成品便宜。

锁是跨线程 + 跨进程的

RLock 管线程，flock 管进程，两层都要。

worktree 是可选机制

不建就没有独立目录；建了也只是工作目录隔离，不是权限或安全隔离。

完成要验 owner

防止 A 把 B 的任务标成完成。

容易踩的坑

  • 把 worktree 当沙箱：它只是另一个 git 工作目录，文件系统权限完全一样。
  • 锁粒度太大（锁住整个任务执行），并行退化成串行。
  • worktree 建了没清理，磁盘里堆一堆分支和目录。
  • 队友之间看不到彼此进度，重复调研同一件事。

动手改一改

起两个队友同时抢同一个任务。验收：第二个收到「already owned / must finish」之类的拒绝，而不是也返回 Claimed。再给其中一个建 worktree，验收：它的文件工具 cwd 指向新目录，另一个仍在原目录。
