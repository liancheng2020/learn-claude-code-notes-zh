知识用到时再加载Skill Loading

目录常驻，正文按需

解决什么问题 · 「怎么写测试」「怎么发版」这类知识篇幅很大。全塞进 system prompt，每轮都要为它付 token，而且大多数时候根本用不上。

思路

  1. 技能 = 一个目录 + 一个 SKILL.md；
  2. 启动时扫描，只把「名字 + 一句话描述」放进 system prompt；
  3. 模型需要时调 load_skill 取全文；
  4. 找不到技能就告诉它有哪些可选。

技能加载器：扫描磁盘、解析元信息、建目录、按名取正文。整个机制不到 80 行。

L60–66

手写 frontmatter 解析：第一个 --- 和第二个 --- 之间是 YAML，之后是正文。用 yaml.safe_load 而不是 eval。

L67–95

约定优于配置：skills/<名字>/SKILL.md。没有注册表，没有配置文件，目录结构就是协议。

L96–103

frontmatter 里没写 name 就用目录名兜底，少一个必填字段就少一处出错。

L104–115

目录只有「名字 + 一句话」。这一行的成本很低，却能换来模型「知道有哪些技能」。

L116–123

按名取全文；取不到时把可选项列出来，模型才知道自己记错了名字。

L124–139

目录进 system prompt，正文留在磁盘。这就是「渐进披露」：先知道有什么，再决定读哪个。

L140–144

system prompt 在进程启动时构建一次。技能是静态的，不需要每轮重扫。

记住这几条

两级加载

目录便宜（常驻），正文贵（按需）。这是所有「知识库」的基本套路。

目录结构即协议

不用写注册表，加技能就是加目录。

描述决定命中率

一句话描述写不清楚，模型永远不知道该加载哪个技能。

取不到要有反馈

返回错误时附上可用列表，比单纯说「不存在」有用得多。

容易踩的坑

  • 一次把五个技能全加载进来，省下的 token 又还回去了。
  • 技能正文和 system prompt 冲突时，这一版没有优先级或冲突检测机制，只能靠模型自己权衡；生产环境需要你显式规定谁优先。
  • 技能目录太大，光目录就占了几千 token。

动手改一改

在 skills/ 下加一个目录，写一个只含 name、description 和三条规则的 SKILL.md。验收：重启后 system prompt 的目录里出现它；模型在相关任务里调用 load_skill 能取到全文。
